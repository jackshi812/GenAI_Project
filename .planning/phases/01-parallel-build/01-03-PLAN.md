  <action>
Create `voice/tts.py` with two functions.

`cap_for_speech(text, max_words=30) -> str` truncates to at most `max_words` words, cutting at the last sentence boundary within the limit when one exists so the answer does not end mid-phrase.

**Thirty, not forty.** Speech runs around 150 words per minute, so forty words is roughly sixteen seconds and spec §127's ceiling is fifteen — forty words fails the requirement outright. Thirty lands near twelve seconds and leaves headroom, which is needed because a word count is not a duration guarantee: product names, dollar amounts and long brand strings all synthesize slower than ordinary prose. Ginger's answerer prompt targets 30 words; this is the enforcement that makes VOICE-04 true regardless of what the model produces on the day.

`synthesize(text) -> bytes` calls `client.audio.speech.create` with `model=os.getenv("TTS_MODEL", "gpt-4o-mini-tts")`, `voice=os.getenv("TTS_VOICE", "alloy")`, and the capped input, returning MP3 bytes. Call `cap_for_speech` inside `synthesize` so nothing can bypass it.

Fragment-based: generate the complete MP3, then play it. Spec §125 permits exactly this.

Add an `if __name__ == "__main__"` block that synthesizes **each of the three canonical answers** — realistic 30-word answers naming a product, a price and a rating — writing `out_1.mp3`, `out_2.mp3`, `out_3.mp3` and printing each word count and byte size.

Do not add a duration-measurement dependency. Play all three with a stopwatch and confirm each is at or under 15.0 seconds. Three files, not one: the fifteen-second ceiling has to hold for whatever you actually demo, and the conflict answer is the longest of the three because it names two prices.

## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser microphone → `voice/stt.py` | User-supplied audio crosses into an external API call |
| `.env` → committed repository | The one place a secret could leak into git history |
| PyPI → `requirements.txt` | Package names are typed by hand |
| Live result URLs → rendered links | Third-party URLs become clickable elements on the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-01 | Information Disclosure | API keys | high | mitigate | `.gitignore` covers `.env`; `.env.example` carries names with empty values only (DOC-04, spec §236); keys read solely via `os.getenv` and never rendered on the page |
| T-03-SC | Tampering | `pip install -r requirements.txt` | high | mitigate | All thirteen packages are major first-party or well-known projects; verify each name on pypi.org before the first install (typosquat check) and pin every line with an exact `==` version read from `pip freeze` |
| T-03-02 | Information Disclosure | Recorded audio | low | accept | Audio is sent to OpenAI for transcription and never written to disk; single-session demo with no persistence |
| T-03-03 | Tampering | Live result URLs rendered in the citations panel | medium | mitigate | Only URLs that passed Austin's retailer allowlist in `mcp_server/web_search.py` reach the interface (D-07); render the domain as the visible label so the destination is legible before clicking |
| T-03-04 | Spoofing | Fabricated ratings on screen | medium | mitigate | The private rating column always renders an em dash with an explicit "no ratings in the 2020 catalog" caption; the interface has no code path that can invent a rating |
| T-03-05 | Denial of Service | Repeated transcription on Streamlit rerun | low | mitigate | Guard on an audio-bytes hash held in `st.session_state` so a rerun cannot re-call the transcription API |
